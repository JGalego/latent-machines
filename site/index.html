Latent Machines

Neural Models as Programmable Machines

João Galego

Preprint. Work in progress; results are added as runs are recorded.

Abstract

Language models that need exact computation typically call external tools, exchanging requests and results as text. An alternative is an internal interface, through which a model issues typed actions to a machine and receives typed observations within its own computation. Studying such an interface first requires machines that execute exactly when expressed in neural-network arithmetic. We separate the machine specification, its implementation, the controller interface, and the task, and we check every implementation against an independent integer oracle after every action, recording the residue of stored values before they are decoded. We implement a random-access memory in the state matrix of a Gated DeltaNet recurrence, finite-state transducers as two-layer ReLU lookup circuits, and a bounded stack built from delta-rule memory and a one-hot pointer. On CPU, in float32, float64, bfloat16, and float16, {{abstract_result}}. These are finite conformance results rather than proofs. In a comparison of learned controllers built on a frozen 135M-parameter language model, a typed internal interface answered more questions correctly than a textual tool on programs longer than those seen in training, and compiled and native executors gave identical answers; all controllers degraded on long programs.

1 Introduction

Language models that need exact computation are commonly paired with external tools: the model writes a request as text, a conventional program executes it, and the result is appended to the context. Recent systems compile complete machines into transformer weights {{cite:qwenputer,percepta}}, building on earlier compilers from programs to transformers {{cite:tracr,alta,looped}}. In these systems the model still communicates with the compiled machine through tokens, much as it would with an external tool.

We ask whether a model benefits from acting on a machine through an internal interface instead, and if so whether the benefit comes from the interface or from compiling the machine into the network. Answering either question requires a machine whose neural implementation is exact. Agreement on final answers is insufficient for this purpose, because an implementation can produce correct outputs while its stored state drifts.

We therefore treat exactness as a property to be tested at every step. The program separates four components: the machine, a specified transition function with an integer reference implementation (the oracle); the backend, which implements the machine in conventional code or tensor arithmetic; the interface, which determines what a controller observes and how it acts; and the task, which supplies inputs and ground truth. An experiment varies one component while holding the others fixed.

This report makes the following contributions:

  • A conformance protocol that compares a backend with its oracle after every action, records the residue of stored values before decoding, and checks that a snapshot restored through JSON reproduces the live state exactly (Section 3.1).
  • Tensor implementations of a random-access memory, finite-state transducers, and a bounded stack, using the Gated DeltaNet recurrence and ReLU lookup circuits (Sections 3.2–3.4).
  • Conformance results for these implementations in four floating-point formats on CPU, with up to 106 actions per configuration (Section 4).
  • A comparison of learned controllers on a record-update task that separates the effect of the interface from the effect of compiling the machine (Section 5).

Code, run records, and per-experiment reports are public.

2 Related work

Programs compiled into neural networks. Tracr {{cite:tracr}} compiles RASP programs into transformer weights, and ALTA {{cite:alta}} extends compilation to looped transformers with categorical state. Giannou et al. {{cite:looped}} construct a looped transformer that executes a simple instruction set, with an analysis of accumulated approximation error. Qwenputer {{cite:qwenputer}} adds a compiled RISC-V CPU to a pretrained language model and stores its registers and memory in Gated DeltaNet state; QwenFX {{cite:qwenfx}} runs a coding agent on that CPU, which in turn calls the same model. Percepta {{cite:percepta}} compiles a WebAssembly interpreter into attention over an append-only execution trace, as does chipformer {{cite:chipformer}} for CHIP-8. Neural Comprehension {{cite:comprehension}} combines compiled modules with a language model's output distribution, and Tracr-Injection {{cite:injection}} trains a language model's residual stream to imitate a compiled program. None of the systems above evaluates a learned internal interface against matched textual-tool and native baselines.

Learned controllers with explicit memory. Neural Turing Machines {{cite:ntm}} and the Differentiable Neural Computer {{cite:dnc}} learn soft read and write operations over external memory. Neural Programmer-Interpreters {{cite:npi}}, Neural Random-Access Machines {{cite:nram}}, the Neural Harvard Computer {{cite:nhc}}, and differentiable Forth {{cite:forth}} learn to control program or memory operations, typically on algorithmic tasks and without a pretrained language model. ToolkenGPT {{cite:toolken}} learns tool embeddings for a frozen language model, while arguments remain textual and tools execute externally.

Linear recurrences as memory. Schlag et al. {{cite:fwp}} relate linear attention to fast-weight programmers that write memory with the delta rule. Gated DeltaNet {{cite:gdn}} adds a decay gate to the delta rule, and our memory backend uses its recurrence. Allowing negative eigenvalues in the state transition {{cite:negeig,deltaproduct}} extends the state-tracking capacity of linear recurrences, which is relevant to the parity and permutation targets in Section 3.3.

3 Method

3.1 Machines, backends, and conformance

A machine is a transition function

$$ T : (s, a) \mapsto (s', e, w), \tag{{{eqtag:transition}}} $$

mapping a state \(s\) and an action \(a\) to a next state \(s'\), an event \(e\) (continue, output with a value, halt, or fault with a reason), and a work count \(w\). Invalid actions produce faults and leave the state unchanged; values are never clamped or wrapped. Each machine has an integer oracle that implements \(T\) directly. A backend implements the same transitions on its own state \(\sigma\) and provides a decoding \(\mathrm{dec}(\sigma)\) to canonical machine state, used only for checking and never shown to a controller ({{fig:components}}).

Given a sequence of actions, we step the oracle and the backend together. Step \(t\) conforms if the events and work counts are equal and \(\mathrm{dec}(\sigma_t) = s_t\); a run stops at the first nonconforming step. We also record the residue

$$ \rho(\sigma) = \max_i \, \min\!\big(|\sigma_i|,\ |\sigma_i - 1|\big), \tag{{{eqtag:residue}}} $$

the largest distance of any stored value from 0 or 1. Decoding thresholds each value at 0.5, so a nonzero residue can coexist with correct outputs; recording \(\rho\) exposes this loss of margin. Midway through each run, the decoded state is serialized to JSON, restored, and re-encoded, and the result must equal the live backend state exactly. A backend is exact on a run if every step conforms, \(\rho = 0\) throughout, and the snapshot check passes.

3.2 Random-access memory in a delta-rule state matrix

The Gated DeltaNet recurrence {{cite:gdn}} updates a state matrix \(S_t\) with a key \(k_t\), value \(v_t\), retention gate \(\alpha_t\), and write strength \(\beta_t\), and reads with a query \(q_t\):

$$ S_t = \alpha_t\, S_{t-1}\big(I - \beta_t k_t k_t^\top\big) + \beta_t\, v_t k_t^\top, \qquad o_t = S_t q_t. \tag{{{eqtag:delta}}} $$

We store a memory of \(N\) words of \(B\) bits in \(S \in \mathbb{R}^{B \times N}\), one column per slot and one row per bit. A write to slot \(j\) uses \(k_t = e_j\), the bits of the word as \(v_t\), \(\alpha_t = 1\), and \(\beta_t = 1\); a read uses \(\beta_t = 0\) and \(q_t = e_j\). Keys and queries are normalized as \(x / \max(\lVert x \rVert, \epsilon)\), which leaves one-hot vectors unchanged. The computation is evaluated as \(\alpha(S - \beta (S k) k^\top) + \beta v k^\top\) without forming the \(N \times N\) transition matrix.

Under these settings every entry of \(S\) stays in \(\{0, 1\}\). Each product in Equation {{eq:delta}} then involves only 0 and 1, each sum has at most one nonzero term, and the subtraction that clears column \(j\) computes \(x - x = 0\), so every operation is exact in any binary floating-point format and the update replaces column \(j\) while leaving the others unchanged. The argument depends on the gates being exactly 0 or 1 and on the normalization leaving one-hot keys unchanged. A retention gate slightly below 1, or a normalization that adds \(\epsilon\) inside the square root, breaks it, as {{fig:playground}} shows. Host code checks addresses and values before the tensor update, and invalid actions do not modify \(S\).

3.3 Finite-state transducers as ReLU lookup circuits

A deterministic transducer with states \(Q\), input alphabet \(\Sigma\), transition table \(\delta\), and output table \(\lambda\) is compiled into a two-layer ReLU network with feedback. The state is a one-hot vector \(s \in \{0,1\}^{|Q|}\) and the input symbol a one-hot vector \(x \in \{0,1\}^{|\Sigma|}\):

$$ z = \mathrm{ReLU}\big(W_{\mathrm{in}} [s; x] - \mathbf{1}\big), \qquad s' = W_{\mathrm{next}}\, z, \qquad y = W_{\mathrm{out}}\, z. \tag{{{eqtag:lookup}}} $$

The hidden layer has one unit for each pair \((q, \sigma)\), with weight 1 on \(s_q\) and on \(x_\sigma\), so the unit is 1 exactly when both inputs are active. Its outgoing weights select \(\delta(q, \sigma)\) in \(W_{\mathrm{next}}\) and \(\lambda(q, \sigma)\) in \(W_{\mathrm{out}}\). The circuit has width \(|Q||\Sigma|\), depth 2, and four nonzero weights per hidden unit, and every intermediate value is an integer between \(-1\) and 2. We compile three targets: running parity, a counter modulo 5 over increments 0–2, and tracking of a permutation of three items under adjacent transpositions, for which the order of inputs matters.

3.4 A bounded stack

A stack of capacity \(N\) stores its items in a delta-rule matrix as in Section 3.2 and its depth in a one-hot pointer \(p \in \{0,1\}^{N+1}\). With the shift matrix \(U\) defined by \(U_{d+1,d} = 1\),

$$ \begin{aligned} \textsf{push}(v)&:\quad S \leftarrow S + (v - S p_{1:N})\, p_{1:N}^\top,\quad p \leftarrow U p, \\ \textsf{pop}&:\quad p \leftarrow U^\top p,\quad o = S p_{1:N},\quad S \leftarrow S - (S p_{1:N})\, p_{1:N}^\top. \end{aligned} \tag{{{eqtag:stack}}} $$

Pop clears the freed slot, so the tensors always equal the encoding of the canonical stack. Overflow and underflow are read from the entries \(p_{N+1}\) and \(p_1\) of the pointer itself.

4 Experiments

4.1 Setup

E00 (memory). A memory of 16 words of 8 bits is driven by eight workloads: repeated overwrites of one slot, alternating addresses, writes confined to half of memory, long idle stretches, clearing of contiguous regions, cycles that fill and read every slot, interleaved invalid addresses and values, and random mixtures.

E01 (streaming machines). The three transducers of Section 3.3 receive random symbols, of which about 5% are outside the alphabet. A stack of capacity 8 with 8-bit words is driven by a bracket-matching parser, by random pushes and pops, and by cycles that push past capacity and pop past empty.

Protocol. Every workload is run in float32, float64, bfloat16, and float16. Sweeps of 103 actions per configuration use three seeds; sweeps of 105 and 106 actions use one. All runs use eager PyTorch 2.15 on CPU, either on an Intel i7-1365U or on Hugging Face Jobs (AMD EPYC 7R13, 8 CPUs), from committed source revisions recorded with each run.

5 Learned controllers

Experiment E02 compares learned controllers on a record-update task. Programs such as “Set c to 7. What is c?” assign values from 0 to 15 to eight records and ask for their current values. A frozen SmolLM2-135M model reads each program, and only small heads that read its hidden states are trained: an action head that chooses an operation, a record, and a value, and an answer head. The four arms in {{tab:e02-arms}} share the task, the frozen features, and the head architecture.

Controllers are trained on programs of 2 to 8 statements and evaluated without teacher forcing, so a wrong write affects later answers. The test programs have the training length, 32 statements, or 64 statements, or use record-value pairs withheld from training; every arm is trained with three seeds and evaluated on the same programs. {{tab:e02-566e}} reports the results. The typed interface (C) answered more questions correctly than the text tool (B) on every split and seed. Beyond the training length and on held-out pairs the mean difference was 0.06 to 0.10, larger than a conservative two-standard-error bound; at the training length it was 0.02, within that bound. B chose actions more accurately than C, so C's advantage arises after the action is chosen. Replacing the integer oracle with the delta-rule memory (D) changed no answer, and the delta-rule executor matched its shadow oracle on every action. All arms degraded on longer programs, and so did the accuracy of the chosen actions; there, the controller rather than the machine limits accuracy. Later experiments ({{fig:roadmap}}) test non-text feedback into the model and machines beyond random-access memory.

6 Limitations

The results are conformance tests on finite workloads and do not prove exactness for other inputs, sizes, or horizons. All runs use eager PyTorch on CPU; GPUs, fused or chunked kernels, and the output normalization and gating of a complete Gated DeltaNet layer are untested, and Section 3.2 shows that such details can matter. The machines are small: 16 memory words, transducers with at most six states, and a stack of depth 8. Host code validates arguments before the tensor update, so the results concern storage, readout, and transitions rather than validation. The sweeps of 105 and 106 actions use a single seed. The controller study uses one frozen 135M-parameter model with trained heads, one task, and three seeds, and its typed observations reach only the answer head, not later layers of the model.

7 Conclusion

With gates fixed at 0 or 1 and one-hot addressing, the Gated DeltaNet recurrence implements random-access memory and, with a one-hot pointer, a bounded stack; two-layer ReLU circuits implement finite-state transducers. In the tested configurations, each implementation matched its integer oracle at every action with zero residue. With these executors, a controller built on a frozen language model answered more questions correctly through a typed internal interface than through a textual tool on programs longer than those seen in training, and the compiled executor gave the same answers as the native one. On long programs the controller's actions limit accuracy, which the next experiments address.
