Latent Machines

Neural models as programmable machines

João Galego · ongoing research, updated as results land

TL;DR

We compile small exact machines (a memory, a stack, state machines) into the arithmetic of neural network layers and check them against a plain reference after every single step. So far they agree exactly: 35 million memory actions with zero disagreements and zero drift. Next we ask whether a language model does better using such a machine internally than calling a tool.

The question

Language models call tools through text. Could the tool live inside the model instead?

Today a language model that needs exact computation writes a tool call as text, waits for a reply, and reads it back. Recent work shows that whole computers can be compiled into a model's weights, but the model usually still talks to them like a tool. We want to know two things:

  • Can a model use a machine through an internal interface instead of textual tool calls?
  • When does this improve correctness, generalization, or cost?

Before a model can rely on a machine inside itself, that machine has to be exact. "Exact" here means matching a specified machine within declared number formats and resource limits, checked at every step, not just producing plausible output.

Four separate questions

What runs, how it runs, how it is controlled, and what it is for are tested separately.

Every backend is checked against an independent oracle. The dotted check path never reaches the controller, so it cannot leak answers.

Separating these axes lets each experiment change one thing. A positive result must say whether it came from the interface, from compiling the machine into weights, or from the task.

Memory inside a neural layer

One update rule from modern linear-attention layers overwrites a memory slot exactly, if its gates sit exactly at 0 or 1.

Gated DeltaNet layers carry a state matrix S from token to token and update it with the delta rule:

S ← α · S (I − β k kᵀ) + β v kᵀ   and reads are   o = S q

Store one memory slot per column and one bit per row. A one-hot key k picks the slot, v holds the word's bits, and with α = 1 and β = 1 the update replaces that column and touches nothing else. Reads, idles, and halts run the same update with β = 0.

    Each cell is one entry of S; the bottom rows compare the decoded words with an exact integer oracle. Turn on a toggle and repeat actions: a gate just below 1 slowly erases memory, and the kernel-style norm leaves reads correct while each value it writes drifts by about 5 × 10⁻⁷. Only the residue shows it.

    Every number below is generated from committed run records; nothing is typed in by hand.

    Each run steps the oracle and the neural backend side by side and checks every action: same event, same work, same decoded state, plus the residue, the largest distance of any stored value from an exact 0 or 1.     Related work

    Others have put computers in weights; the open part is a learned internal interface, compared fairly.

    The idea is not new. Qwenputer compiles a RISC-V CPU into Qwen3.5 with Gated DeltaNet state as RAM, Percepta compiles a WebAssembly interpreter into attention, Neural Comprehension lets compiled modules steer decoding, and Tracr compiles programs into transformers. Learned controllers over explicit memory go back to Neural Turing Machines and Neural Programmer-Interpreters. Our research notes record what each establishes and where it stops.
