Latent Machines

Neural Models as Programmable Machines

João Galego

Preprint. Work in progress; results are added as runs are recorded.

Abstract

Language models that need exact computation typically call external tools, exchanging requests and results as text. An alternative is an internal interface, through which a model issues typed actions to a machine and receives typed observations within its own computation. Studying such an interface first requires machines that execute exactly when expressed in neural-network arithmetic. We separate the machine specification, its implementation, the controller interface, and the task, and we check every implementation against an independent integer oracle after every action, recording the residue of stored values before they are decoded. We implement a random-access memory in the state matrix of a Gated DeltaNet recurrence, finite-state transducers as two-layer ReLU lookup circuits, and a bounded stack built from delta-rule memory and a one-hot pointer. On CPU, in float32, float64, bfloat16, and float16, {{abstract_result}}. These are finite conformance results rather than proofs. In a comparison of learned controllers built on a frozen 135M-parameter language model, a typed internal interface answered more questions correctly than a textual tool on programs longer than those seen in training, and compiled and native executors gave identical answers; all controllers degraded on long programs. When the result of each machine step re-entered the model as a trained input vector, accuracy on long multi-step programs rose far above text, head, and native-loop feedback, but a control whose vectors carried no feedback did nearly as well: the gain came mostly from trained inputs, not from latent feedback. Tensor implementations of dataflow graphs, graph and Datalog fixed points, cellular automata, optimizer-written memory, and a SAT verifier matched their references in float32 and float64 within declared limits, were rarely faster than conventional algorithms, and failed in bfloat16 wherever an integer or coefficient needed more precision than it has.

1 Introduction

Language models that need exact computation are commonly paired with external tools: the model writes a request as text, a conventional program executes it, and the result is appended to the context. Recent systems compile complete machines into transformer weights {{cite:qwenputer,percepta}}, building on earlier compilers from programs to transformers {{cite:tracr,alta,looped}}. In these systems the model still communicates with the compiled machine through tokens, much as it would with an external tool.

We ask whether a model benefits from acting on a machine through an internal interface instead, and if so whether the benefit comes from the interface or from compiling the machine into the network. Answering either question requires a machine whose neural implementation is exact. Agreement on final answers is insufficient for this purpose, because an implementation can produce correct outputs while its stored state drifts.

We therefore treat exactness as a property to be tested at every step. The program separates four components: the machine, a specified transition function with an integer reference implementation (the oracle); the backend, which implements the machine in conventional code or tensor arithmetic; the interface, which determines what a controller observes and how it acts; and the task, which supplies inputs and ground truth. An experiment varies one component while holding the others fixed.

This report makes the following contributions:

  • A conformance protocol that compares a backend with its oracle after every action, records the residue of stored values before decoding, and checks that a snapshot restored through JSON reproduces the live state exactly (Section 3.1).
  • Tensor implementations of a random-access memory, finite-state transducers, and a bounded stack, using the Gated DeltaNet recurrence and ReLU lookup circuits (Sections 3.2–3.4).
  • Conformance results for these implementations in four floating-point formats on CPU, with up to 106 actions per configuration (Section 4).
  • Conformance results for dataflow graphs, graph and Datalog fixed points, cellular automata and linear filters, optimizer-defined memories, and a compiled SAT verifier, including the formats and sizes at which they fail (Section 4).
  • A comparison of learned controllers on a record-update task that separates the effect of the interface from the effect of compiling the machine, and a multi-step extension with a control that separates latent feedback from trained input vectors (Section 5).

Code, run records, and per-experiment reports are public.

2 Related work

Programs compiled into neural networks. Tracr {{cite:tracr}} compiles RASP programs into transformer weights, and ALTA {{cite:alta}} extends compilation to looped transformers with categorical state. Giannou et al. {{cite:looped}} construct a looped transformer that executes a simple instruction set, with an analysis of accumulated approximation error. Qwenputer {{cite:qwenputer}} adds a compiled RISC-V CPU to a pretrained language model and stores its registers and memory in Gated DeltaNet state; QwenFX {{cite:qwenfx}} runs a coding agent on that CPU, which in turn calls the same model. Percepta {{cite:percepta}} compiles a WebAssembly interpreter into attention over an append-only execution trace, as does chipformer {{cite:chipformer}} for CHIP-8. Neural Comprehension {{cite:comprehension}} combines compiled modules with a language model's output distribution, and Tracr-Injection {{cite:injection}} trains a language model's residual stream to imitate a compiled program. None of the systems above evaluates a learned internal interface against matched textual-tool and native baselines.

Learned controllers with explicit memory. Neural Turing Machines {{cite:ntm}} and the Differentiable Neural Computer {{cite:dnc}} learn soft read and write operations over external memory. Neural Programmer-Interpreters {{cite:npi}}, Neural Random-Access Machines {{cite:nram}}, the Neural Harvard Computer {{cite:nhc}}, and differentiable Forth {{cite:forth}} learn to control program or memory operations, typically on algorithmic tasks and without a pretrained language model. ToolkenGPT {{cite:toolken}} learns tool embeddings for a frozen language model, while arguments remain textual and tools execute externally.

Linear recurrences as memory. Schlag et al. {{cite:fwp}} relate linear attention to fast-weight programmers that write memory with the delta rule. Gated DeltaNet {{cite:gdn}} adds a decay gate to the delta rule, and our memory backend uses its recurrence. Allowing negative eigenvalues in the state transition {{cite:negeig,deltaproduct}} extends the state-tracking capacity of linear recurrences, which is relevant to the parity and permutation targets in Section 3.3.

3 Method

3.1 Machines, backends, and conformance

A machine is a transition function

$$ T : (s, a) \mapsto (s', e, w), \tag{{{eqtag:transition}}} $$

mapping a state \(s\) and an action \(a\) to a next state \(s'\), an event \(e\) (continue, output with a value, halt, or fault with a reason), and a work count \(w\). Invalid actions produce faults and leave the state unchanged; values are never clamped or wrapped. Each machine has an integer oracle that implements \(T\) directly. A backend implements the same transitions on its own state \(\sigma\) and provides a decoding \(\mathrm{dec}(\sigma)\) to canonical machine state, used only for checking and never shown to a controller ({{fig:components}}).

Given a sequence of actions, we step the oracle and the backend together. Step \(t\) conforms if the events and work counts are equal and \(\mathrm{dec}(\sigma_t) = s_t\); a run stops at the first nonconforming step. We also record the residue

$$ \rho(\sigma) = \max_i \, \min\!\big(|\sigma_i|,\ |\sigma_i - 1|\big), \tag{{{eqtag:residue}}} $$

the largest distance of any stored value from 0 or 1. Decoding thresholds each value at 0.5, so a nonzero residue can coexist with correct outputs; recording \(\rho\) exposes this loss of margin. Midway through each run, the decoded state is serialized to JSON, restored, and re-encoded, and the result must equal the live backend state exactly. A backend is exact on a run if every step conforms, \(\rho = 0\) throughout, and the snapshot check passes.

3.2 Random-access memory in a delta-rule state matrix

The Gated DeltaNet recurrence {{cite:gdn}} updates a state matrix \(S_t\) with a key \(k_t\), value \(v_t\), retention gate \(\alpha_t\), and write strength \(\beta_t\), and reads with a query \(q_t\):

$$ S_t = \alpha_t\, S_{t-1}\big(I - \beta_t k_t k_t^\top\big) + \beta_t\, v_t k_t^\top, \qquad o_t = S_t q_t. \tag{{{eqtag:delta}}} $$

We store a memory of \(N\) words of \(B\) bits in \(S \in \mathbb{R}^{B \times N}\), one column per slot and one row per bit. A write to slot \(j\) uses \(k_t = e_j\), the bits of the word as \(v_t\), \(\alpha_t = 1\), and \(\beta_t = 1\); a read uses \(\beta_t = 0\) and \(q_t = e_j\). Keys and queries are normalized as \(x / \max(\lVert x \rVert, \epsilon)\), which leaves one-hot vectors unchanged. The computation is evaluated as \(\alpha(S - \beta (S k) k^\top) + \beta v k^\top\) without forming the \(N \times N\) transition matrix.

Under these settings every entry of \(S\) stays in \(\{0, 1\}\). Each product in Equation {{eq:delta}} then involves only 0 and 1, each sum has at most one nonzero term, and the subtraction that clears column \(j\) computes \(x - x = 0\), so every operation is exact in any binary floating-point format and the update replaces column \(j\) while leaving the others unchanged. The argument depends on the gates being exactly 0 or 1 and on the normalization leaving one-hot keys unchanged. A retention gate slightly below 1, or a normalization that adds \(\epsilon\) inside the square root, breaks it, as {{fig:playground}} shows. Host code checks addresses and values before the tensor update, and invalid actions do not modify \(S\).

3.3 Finite-state transducers as ReLU lookup circuits

A deterministic transducer with states \(Q\), input alphabet \(\Sigma\), transition table \(\delta\), and output table \(\lambda\) is compiled into a two-layer ReLU network with feedback. The state is a one-hot vector \(s \in \{0,1\}^{|Q|}\) and the input symbol a one-hot vector \(x \in \{0,1\}^{|\Sigma|}\):

$$ z = \mathrm{ReLU}\big(W_{\mathrm{in}} [s; x] - \mathbf{1}\big), \qquad s' = W_{\mathrm{next}}\, z, \qquad y = W_{\mathrm{out}}\, z. \tag{{{eqtag:lookup}}} $$

The hidden layer has one unit for each pair \((q, \sigma)\), with weight 1 on \(s_q\) and on \(x_\sigma\), so the unit is 1 exactly when both inputs are active. Its outgoing weights select \(\delta(q, \sigma)\) in \(W_{\mathrm{next}}\) and \(\lambda(q, \sigma)\) in \(W_{\mathrm{out}}\). The circuit has width \(|Q||\Sigma|\), depth 2, and four nonzero weights per hidden unit, and every intermediate value is an integer between \(-1\) and 2. We compile three targets: running parity, a counter modulo 5 over increments 0–2, and tracking of a permutation of three items under adjacent transpositions, for which the order of inputs matters.

3.4 A bounded stack

A stack of capacity \(N\) stores its items in a delta-rule matrix as in Section 3.2 and its depth in a one-hot pointer \(p \in \{0,1\}^{N+1}\). With the shift matrix \(U\) defined by \(U_{d+1,d} = 1\),

$$ \begin{aligned} \textsf{push}(v)&:\quad S \leftarrow S + (v - S p_{1:N})\, p_{1:N}^\top,\quad p \leftarrow U p, \\ \textsf{pop}&:\quad p \leftarrow U^\top p,\quad o = S p_{1:N},\quad S \leftarrow S - (S p_{1:N})\, p_{1:N}^\top. \end{aligned} \tag{{{eqtag:stack}}} $$

Pop clears the freed slot, so the tensors always equal the encoding of the canonical stack. Overflow and underflow are read from the entries \(p_{N+1}\) and \(p_1\) of the pointer itself.

4 Experiments

4.1 Setup

E00 (memory). A memory of 16 words of 8 bits is driven by eight workloads: repeated overwrites of one slot, alternating addresses, writes confined to half of memory, long idle stretches, clearing of contiguous regions, cycles that fill and read every slot, interleaved invalid addresses and values, and random mixtures.

E01 (streaming machines). The three transducers of Section 3.3 receive random symbols, of which about 5% are outside the alphabet. A stack of capacity 8 with 8-bit words is driven by a bracket-matching parser, by random pushes and pops, and by cycles that push past capacity and pop past empty.

E04 (dataflow). Integer programs over 16-bit signed words (random expression graphs of 30 operations, a 64-element dot product, and a gather/map/reduce/scatter pipeline) are evaluated with Python integers, with int64 tensors, by a scalar machine that executes one node per instruction with its operands in delta-rule memory, and by tensor programs that compute one level of the graph per step, using gathered operands, program-specialized weight matrices, or expert dispatch with a fixed capacity per round. Overflow faults at the first out-of-range node. Before the runs, bfloat16 and float16 were declared precision probes outside the acceptance.

E05 (graphs and logic). Transitive closure, all-pairs shortest paths with nonnegative integer weights and a declared distance bound, and a recursive Datalog program run as fixed-point machines with one synchronous round per step. Dense Boolean and min-plus tensor rounds are compared with integer oracles after every round on random graphs that include disconnected vertices, equal-length paths, and long chains.

E06 (grids and filters). In the exact branch, three outer-totalistic cellular rules on 32×32 grids with zero and toroidal boundaries are implemented as a 3×3 convolution that counts neighbors followed by a ReLU lookup. In the numerical branch, three linear filters run as dense and diagonal state-space recurrences, sequentially and in chunks, against a float64 reference. Tolerances on the maximum error relative to the reference's RMS were fixed before the recorded runs: 10−9, 10−4, and 10−2 for float64, float32, and bfloat16.

E07 (optimizer-defined memory). A 16×8 linear memory is written by one optimizer step per action on ½‖Wk − v‖². Starting from sequential SGD with learning rate 1, one feature changes at a time: the learning rate, gradients frozen at the start of a chunk, momentum, decay, gradient normalization, or an MLP in place of the matrix. Each implementation must match an independent float64 reference at every step; agreement with the memory oracle is reported as a finding, not required.

E08 (search with a verifier). Random 3-SAT instances with 20 to 100 variables, planted or uniform, some unsatisfiable. A verifier compiled from clause–literal incidence matrices is compared with an integer verifier on 60,000 candidate assignments. Four search procedures receive 20,000 steps per instance: a complete DPLL solver, WalkSAT, random proposals, and Langevin descent on a relaxed clause energy. The descent proposals are checked by the integer verifier and by the compiled one.

Protocol. E00 and E01 workloads run in float32, float64, bfloat16, and float16; sweeps of 103 actions per configuration use three seeds, and sweeps of 105 and 106 actions use one. E04–E08 use one or two seeds and the formats listed in their tables. All runs use eager PyTorch 2.15 on CPU, either on an Intel i7-1365U or on Hugging Face Jobs (AMD EPYC 7R13, 8 CPUs), from committed source revisions recorded with each run. Timings come from a shared CPU and indicate orders of magnitude, not precise speedups.

4.2 Results

The tables below are generated from the committed run records. {{conformance_summary}} The workloads triggered every specified fault, including invalid addresses and values, invalid symbols, stack overflow, and stack underflow. The bracket-matching workload underflowed but never overflowed at capacity 8; overflow is exercised by the other stack workloads.

Dataflow (E04). In float32 and float64, every tensor lowering matched the oracle on outputs, the faulting node, work, and every intermediate value, and replaced 123–605 scalar-machine instructions with 3–9 level steps. The compiled graphs were no faster than the same schedule in int64 tensors, and slower than Python for single inputs, so we claim no speed advantage. The half-precision probes mismatched on 37–100% of evaluations with zero residue: a value rounded to the wrong integer is still an integer, so only the comparison with the oracle exposes it.

Graphs and logic (E05). Fifty-three of 55 configurations matched their oracles exactly in both runs, including unreachable entries, distance-bound faults, and the round that confirms the fixed point. The two failures are bfloat16 shortest paths, which broke whenever distances exceeded 256, the largest integer bfloat16 represents exactly. On sparse graphs of up to 4,096 vertices, dense tensor rounds were 20 to 100 times slower than breadth-first search and Dijkstra's algorithm.

Grids and filters (E06). The convolution and lookup circuit matched all three cellular rules cell for cell in all four formats over 720,000 actions. The filters stayed within tolerance in float64 and float32 over 105 samples, the largest float32 error approaching its limit. In bfloat16, 17 of 18 filter configurations exceeded their tolerance, the conventional dense recurrence included, because rounding moves a pole radius from 0.999 to 0.998.

Optimizer-defined memory (E07). Sequential SGD with learning rate 1 and one-hot keys matched the memory oracle exactly on all eight memory workloads in float32 and float64, as the delta-rule identity predicts. Every single change departed from replacement: lower learning rates, stale chunk gradients, momentum, decay, gradient normalization, and the MLP memory. In float32 and float64, the implementations still matched their float64 reference at every step. In bfloat16, momentum steps exceeded the reference tolerance, and the decay factor rounded to 1, so decay never happened. A snapshot of the decoded memory words alone cannot resume momentum, which also needs its optimizer buffers.

Search with a verifier (E08). Within its declared integer limits, the compiled verifier agreed with the integer verifier on every candidate and never accepted an invalid assignment. Past bfloat16's limit, a variant with folded weights rejected 119 valid assignments, which the residue did not reveal. Energy-based proposals were far better than random ones and solved 23 of 28 known-satisfiable instances, against 28 for WalkSAT; only DPLL proved unsatisfiability. With identical decisions, the compiled verifier was 11 to 18 times faster than the Python verifier, so faster verification did not make energy search competitive here.

5 Learned controllers

Experiment E02 compares learned controllers on a record-update task. Programs such as “Set c to 7. What is c?” assign values from 0 to 15 to eight records and ask for their current values. A frozen SmolLM2-135M model reads each program, and only small heads that read its hidden states are trained: an action head that chooses an operation, a record, and a value, and an answer head. The four arms in {{tab:e02-arms}} share the task, the frozen features, and the head architecture.

Controllers are trained on programs of 2 to 8 statements and evaluated without teacher forcing, so a wrong write affects later answers. The test programs have the training length, 32 statements, or 64 statements, or use record-value pairs withheld from training; every arm is trained with three seeds and evaluated on the same programs. {{tab:e02-566e}} reports the results. The typed interface (C) answered more questions correctly than the text tool (B) on every split and seed. Beyond the training length and on held-out pairs the mean difference was 0.06 to 0.10, larger than a conservative two-standard-error bound; at the training length it was 0.02, within that bound. B chose actions more accurately than C, so C's advantage arises after the action is chosen. Replacing the integer oracle with the delta-rule memory (D) changed no answer, and the delta-rule executor matched its shadow oracle on every action. All arms degraded on longer programs, and so did the accuracy of the chosen actions; there, the controller rather than the machine limits accuracy.

Experiment E03 asks whether feedback that enters the model, rather than text or the heads, improves control. Its programs add statements such as “Copy c to e.”, which take two machine steps: read c, then write the value read to e. The value is not in the text, so the controller must route the read's reply into its next decision. At every step the controller chooses a write, a read, or the end of the statement, with at most three steps per statement, and the step's action and reply form a small feedback code. The arms in {{tab:e03-arms}} differ only in where that code goes ({{fig:roadmap}} shows how E03 follows E02). All arms drive the delta-rule memory with a shadow oracle.

{{tab:e03-ff00}} reports the results on the same test splits as E02. L and S beat T, H, and N on every split and seed, by 0.08 to 0.17 at the training length and by 0.31 to 0.53 at 32 and 64 statements (seed means), so the gain survives comparison with the native loop. But S, whose vectors carry no feedback, matched or exceeded L up to 32 statements; L led only at 64 statements, by 0.05. Most of the improvement therefore comes from trained vectors in the model's input, not from feedback through the model. L and S also spend more model computation than H and N and train through the frozen model, so this is not a comparison at matched work. Typed feedback to the heads (H) again beat text (T), by 0.04 to 0.07. The delta-rule memory matched its oracle on every action of every arm, and runs interrupted between the read and the write of a copy resumed through JSON identically.

6 Limitations

The results are conformance tests on finite workloads and do not prove exactness for other inputs, sizes, or horizons. All conformance runs use eager PyTorch on CPU; GPUs, fused or chunked kernels, and the output normalization and gating of a complete Gated DeltaNet layer are untested, and Section 3.2 shows that such details can matter. The machines are small: 16 memory words, transducers with at most six states, a stack of depth 8, 32×32 grids, graphs of up to 4,096 vertices, and SAT instances of up to 100 variables. Timings come from shared machines and support orders of magnitude only. Host code validates arguments before the tensor update, so the results concern storage, readout, and transitions rather than validation. The sweeps of 105 and 106 actions use a single seed. The controller studies use one frozen 135M-parameter model with trained heads, one task family, and three seeds. In E03, the latent arms use more model positions than the head and native arms, observation-only feedback was not tested, and the steering control was added after a pilot.

7 Conclusion

With gates fixed at 0 or 1 and one-hot addressing, the Gated DeltaNet recurrence implements random-access memory and, with a one-hot pointer, a bounded stack; two-layer ReLU circuits implement finite-state transducers. In the tested configurations, each implementation matched its integer oracle at every action with zero residue. With these executors, a controller built on a frozen language model answered more questions correctly through a typed internal interface than through a textual tool on programs longer than those seen in training, and the compiled executor gave the same answers as the native one. On long programs the controller's actions limit accuracy. Trained input vectors in the frozen model improved those actions substantially, whether or not they carried the machine's feedback, so the evidence here favors trained steering over latent feedback. The other machines show that exact tensor execution is achievable in float32 and float64 within declared limits, but rarely faster than conventional code; their value, if any, lies in being differentiable or composable with a model, which remains to be shown.
