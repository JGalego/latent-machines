Latent Machines

Neural Models as Programmable Machines

João Galego

Preprint. Work in progress; results are added as runs are recorded.

Can a model use a machine without writing tool calls?

A language model that needs exact state, such as memory it can overwrite, usually calls a tool. It writes a request as text and reads the reply as text. This project asks whether the model can drive a machine through an internal interface instead, and whether that machine can be built from neural-network arithmetic, so that a program runs in the model's own kind of layers.

These are two questions, tested separately. First: does a machine run exactly in layer arithmetic? We check by comparing it with an integer oracle after every action. Second: does a model control it better through an internal interface? We compare controllers on matched tasks. Most results so far answer the first question. The second matters more and has three experiments.

Where the machine stops being the problem

The machine executes exactly, yet every controller gets less accurate on programs longer than the ones it trained on. The controller's actions fail, not the memory. In {{e:E09}}, the same heads read one statement at a time while the machine held everything else. They made no errors up to 256 statements, where full-context controllers fell to about 0.13. So long context was the cause. The task has only 128 distinct statements, so we also tested 8 statements the controller never trained on. It got 7 right, and a random untrained model got 2.

Abstract

Language models that need exact computation usually call external tools and exchange requests and results as text. An alternative is an internal interface: the model issues typed actions to a machine and receives typed observations inside its own computation. Testing this needs machines that run exactly in neural-network arithmetic. We separate the machine specification, its implementation, the controller interface, and the task, and we check every implementation against an independent integer oracle after every action, recording the residue of stored values before they are decoded. We implement a random-access memory in the state matrix of a Gated DeltaNet recurrence, finite-state transducers as two-layer ReLU lookup circuits, and a bounded stack built from delta-rule memory and a one-hot pointer. On CPU, in float32, float64, bfloat16, and float16, {{abstract_result}}. These are finite conformance results, not proofs. With a frozen 135M-parameter language model, a typed internal interface answered more questions correctly than a text tool on programs longer than those seen in training, and compiled and native executors gave identical answers. All controllers got worse on long programs. A controller that read one statement at a time, with the machine holding the state, did not. It also read 7 of 8 statements it had never trained on, but the task is small and its statements are independent. When each machine step re-entered the model as a trained input vector, accuracy on long multi-step programs rose far above text, head, and native-loop feedback. A control whose vectors carried no feedback did nearly as well, so the gain came from trained inputs, not latent feedback. Tensor implementations of dataflow graphs, graph and Datalog fixed points, cellular automata, optimizer-written memory, and a SAT verifier matched their references in float32 and float64 within declared limits. They were rarely faster than conventional algorithms and failed in bfloat16 wherever a value needed more precision than the format has.

1 Introduction

Language models that need exact computation are usually paired with external tools. The model writes a request as text, a conventional program runs it, and the result is appended to the context. Recent systems compile whole machines into transformer weights {{cite:qwenputer,percepta}}, building on earlier compilers from programs to transformers {{cite:tracr,alta,looped}}. The model still talks to the compiled machine through tokens, as it would to an external tool.

We ask whether a model does better acting on a machine through an internal interface, and if so whether the benefit comes from the interface or from compiling the machine into the network. Both questions need a machine whose neural implementation is exact. Matching final answers is not enough, because an implementation can give correct outputs while its stored state drifts.

So we test exactness at every step. The work has four parts. The machine is a transition function with an integer reference implementation, the oracle. The backend implements the machine in conventional code or tensor arithmetic. The interface decides what a controller sees and how it acts. The task supplies inputs and ground truth. Each experiment changes one part and holds the others fixed.

This report contributes:

  • A conformance protocol. It compares a backend with its oracle after every action, records the residue of stored values before decoding, and checks that a snapshot restored through JSON reproduces the live state exactly (Section 3.1).
  • Tensor implementations of a random-access memory, finite-state transducers, and a bounded stack, using the Gated DeltaNet recurrence and ReLU lookup circuits (Sections 3.2–3.4).
  • Conformance results for these implementations in four floating-point formats on CPU, with up to 106 actions per configuration (Section 4).
  • Conformance results for dataflow graphs, graph and Datalog fixed points, cellular automata and linear filters, optimizer-defined memories, and a compiled SAT verifier, including the formats and sizes where they fail (Section 4).
  • Controller comparisons on a record-update task: interface versus compiled machine, a control that separates latent feedback from trained input vectors, and a pre-registered test of whether long context explains the length loss (Section 5).

Code, run records, and per-experiment reports are public.

2 Related work

Programs compiled into neural networks. Tracr {{cite:tracr}} compiles RASP programs into transformer weights. ALTA {{cite:alta}} extends compilation to looped transformers with categorical state. Giannou et al. {{cite:looped}} build a looped transformer that executes a simple instruction set and analyze its accumulated approximation error. Qwenputer {{cite:qwenputer}} adds a compiled RISC-V CPU to a pretrained language model and stores its registers and memory in Gated DeltaNet state. QwenFX {{cite:qwenfx}} runs a coding agent on that CPU, which calls the same model. Percepta {{cite:percepta}} compiles a WebAssembly interpreter into attention over an append-only execution trace, and chipformer {{cite:chipformer}} does the same for CHIP-8. Neural Comprehension {{cite:comprehension}} combines compiled modules with a language model's output distribution. Tracr-Injection {{cite:injection}} trains a language model's residual stream to imitate a compiled program. None of these evaluates a learned internal interface against matched text-tool and native baselines.

Learned controllers with explicit memory. Neural Turing Machines {{cite:ntm}} and the Differentiable Neural Computer {{cite:dnc}} learn soft read and write operations over external memory. Neural Programmer-Interpreters {{cite:npi}}, Neural Random-Access Machines {{cite:nram}}, the Neural Harvard Computer {{cite:nhc}}, and differentiable Forth {{cite:forth}} learn to control program or memory operations, usually on algorithmic tasks and without a pretrained language model. ToolkenGPT {{cite:toolken}} learns tool embeddings for a frozen language model, but its arguments stay textual and its tools run externally.

Linear recurrences as memory. Schlag et al. {{cite:fwp}} relate linear attention to fast-weight programmers, which write memory with the delta rule. Gated DeltaNet {{cite:gdn}} adds a decay gate to the delta rule, and our memory backend uses its recurrence. Allowing negative eigenvalues in the state transition {{cite:negeig,deltaproduct}} extends the state-tracking capacity of linear recurrences, which bears on the parity and permutation targets in Section 3.3.

3 Method

3.1 Machines, backends, and conformance

A machine is a transition function

$$ T : (s, a) \mapsto (s', e, w), \tag{{{eqtag:transition}}} $$

mapping a state \(s\) and an action \(a\) to a next state \(s'\), an event \(e\) (continue, output with a value, halt, or fault with a reason), and a work count \(w\). Invalid actions produce faults and leave the state unchanged. Values are never clamped or wrapped. Each machine has an integer oracle that implements \(T\) directly. A backend implements the same transitions on its own state \(\sigma\) and provides a decoding \(\mathrm{dec}(\sigma)\) to canonical machine state. The decoding is used for checking only and is never shown to a controller ({{fig:components}}).

We step the oracle and the backend together on a sequence of actions. Step \(t\) conforms if the events and work counts are equal and \(\mathrm{dec}(\sigma_t) = s_t\). A run stops at the first step that does not conform. We also record the residue

$$ \rho(\sigma) = \max_i \, \min\!\big(|\sigma_i|,\ |\sigma_i - 1|\big), \tag{{{eqtag:residue}}} $$

the largest distance of any stored value from 0 or 1. Decoding thresholds each value at 0.5, so a nonzero residue can coexist with correct outputs. Recording \(\rho\) exposes that loss of margin. Halfway through each run, the decoded state is serialized to JSON, restored, and re-encoded, and the result must equal the live backend state exactly. A backend is exact on a run if every step conforms, \(\rho = 0\) throughout, and the snapshot check passes.

3.2 Random-access memory in a delta-rule state matrix

The Gated DeltaNet recurrence {{cite:gdn}} updates a state matrix \(S_t\) with a key \(k_t\), value \(v_t\), retention gate \(\alpha_t\), and write strength \(\beta_t\), and reads with a query \(q_t\):

$$ S_t = \alpha_t\, S_{t-1}\big(I - \beta_t k_t k_t^\top\big) + \beta_t\, v_t k_t^\top, \qquad o_t = S_t q_t. \tag{{{eqtag:delta}}} $$

We store a memory of \(N\) words of \(B\) bits in \(S \in \mathbb{R}^{B \times N}\), one column per slot and one row per bit. A write to slot \(j\) uses \(k_t = e_j\), the bits of the word as \(v_t\), \(\alpha_t = 1\), and \(\beta_t = 1\). A read uses \(\beta_t = 0\) and \(q_t = e_j\). Keys and queries are normalized as \(x / \max(\lVert x \rVert, \epsilon)\), which leaves one-hot vectors unchanged. We evaluate \(\alpha(S - \beta (S k) k^\top) + \beta v k^\top\) without forming the \(N \times N\) transition matrix.

Under these settings every entry of \(S\) stays in \(\{0, 1\}\). Each product in Equation {{eq:delta}} then involves only 0 and 1, each sum has at most one nonzero term, and the subtraction that clears column \(j\) computes \(x - x = 0\). Every operation is exact in any binary floating-point format, so the update replaces column \(j\) and leaves the others unchanged. The argument needs the gates to be exactly 0 or 1 and the normalization to leave one-hot keys unchanged. A retention gate slightly below 1, or a normalization that adds \(\epsilon\) inside the square root, breaks it, as {{fig:playground}} shows. Host code checks addresses and values before the tensor update, and invalid actions do not modify \(S\).

3.3 Finite-state transducers as ReLU lookup circuits

A deterministic transducer with states \(Q\), input alphabet \(\Sigma\), transition table \(\delta\), and output table \(\lambda\) compiles into a two-layer ReLU network with feedback. The state is a one-hot vector \(s \in \{0,1\}^{|Q|}\) and the input symbol a one-hot vector \(x \in \{0,1\}^{|\Sigma|}\):

$$ z = \mathrm{ReLU}\big(W_{\mathrm{in}} [s; x] - \mathbf{1}\big), \qquad s' = W_{\mathrm{next}}\, z, \qquad y = W_{\mathrm{out}}\, z. \tag{{{eqtag:lookup}}} $$

The hidden layer has one unit for each pair \((q, \sigma)\), with weight 1 on \(s_q\) and on \(x_\sigma\), so the unit is 1 exactly when both inputs are active. Its outgoing weights select \(\delta(q, \sigma)\) in \(W_{\mathrm{next}}\) and \(\lambda(q, \sigma)\) in \(W_{\mathrm{out}}\). The circuit has width \(|Q||\Sigma|\), depth 2, and four nonzero weights per hidden unit, and every intermediate value is an integer from \(-1\) to 2. We compile three targets: running parity, a counter modulo 5 over increments 0–2, and tracking a permutation of three items under adjacent transpositions, where input order matters.

3.4 A bounded stack

A stack of capacity \(N\) stores its items in a delta-rule matrix as in Section 3.2 and its depth in a one-hot pointer \(p \in \{0,1\}^{N+1}\). With the shift matrix \(U\) defined by \(U_{d+1,d} = 1\),

$$ \begin{aligned} \textsf{push}(v)&:\quad S \leftarrow S + (v - S p_{1:N})\, p_{1:N}^\top,\quad p \leftarrow U p, \\ \textsf{pop}&:\quad p \leftarrow U^\top p,\quad o = S p_{1:N},\quad S \leftarrow S - (S p_{1:N})\, p_{1:N}^\top. \end{aligned} \tag{{{eqtag:stack}}} $$

Pop clears the freed slot, so the tensors always equal the encoding of the canonical stack. Overflow and underflow are read from the pointer entries \(p_{N+1}\) and \(p_1\).

4.2 Results

The tables below are generated from the committed run records. {{conformance_summary}} The workloads triggered every specified fault: invalid addresses and values, invalid symbols, stack overflow, and stack underflow. The bracket-matching workload underflowed but never overflowed at capacity 8. The other stack workloads exercise overflow.

{{e:E04}}. In float32 and float64, every tensor lowering matched the oracle on outputs, the faulting node, work, and every intermediate value. It replaced 123–605 scalar-machine instructions with 3–9 level steps. The compiled graphs were no faster than the same schedule in int64 tensors and slower than Python on single inputs, so we claim no speed advantage. The half-precision probes mismatched on 37–100% of evaluations with zero residue. A value rounded to the wrong integer is still an integer, so only comparison with the oracle exposes the error.

{{e:E05}}. Fifty-three of 55 configurations matched their oracles exactly in both runs, including unreachable entries, distance-bound faults, and the round that confirms the fixed point. The two failures were bfloat16 shortest paths, which broke whenever distances exceeded 256, the largest integer bfloat16 represents exactly. On sparse graphs of up to 4,096 vertices, dense tensor rounds were 20 to 100 times slower than breadth-first search and Dijkstra's algorithm.

{{e:E06}}. The convolution and lookup circuit matched all three cellular rules cell for cell in all four formats over 720,000 actions. The filters stayed within tolerance in float64 and float32 over 105 samples, and the largest float32 error came close to its limit. In bfloat16, 17 of 18 filter configurations exceeded their tolerance, the conventional dense recurrence included, because rounding moves a pole radius from 0.999 to 0.998.

{{e:E07}}. Sequential SGD with learning rate 1 and one-hot keys matched the memory oracle exactly on all eight memory workloads in float32 and float64, as the delta-rule identity predicts. Every single change departed from replacement: lower learning rates, stale chunk gradients, momentum, decay, gradient normalization, and the MLP memory. In float32 and float64 the implementations still matched their float64 reference at every step. In bfloat16, momentum steps exceeded the reference tolerance and the decay factor rounded to 1, so decay never happened. A snapshot of the decoded memory words cannot resume momentum, which also needs its optimizer buffers.

{{e:E08}}. Within its declared integer limits, the compiled verifier agreed with the integer verifier on every candidate and never accepted an invalid assignment. Past bfloat16's limit, a variant with folded weights rejected 119 valid assignments, and the residue did not show it. Energy-based proposals were far better than random ones and solved 23 of 28 known-satisfiable instances, against 28 for WalkSAT. Only DPLL proved unsatisfiability. With identical decisions the compiled verifier was 11 to 18 times faster than the Python verifier, but faster verification did not make energy search competitive.

5 Learned controllers

{{e:E02}} compares learned controllers on a record-update task. Programs such as “Set c to 7. What is c?” assign values from 0 to 15 to eight records and ask for their current values. A frozen SmolLM2-135M model reads each program. Only small heads on its hidden states are trained: an action head that chooses an operation, a record, and a value, and an answer head. The four arms in {{tab:e02-arms}} share the task, the frozen features, and the head architecture.

{{anim:e02}}

Controllers train on programs of 2 to 8 statements and are evaluated without teacher forcing, so a wrong write affects later answers. The test programs have the training length, 32 statements, or 64 statements, or use record-value pairs withheld from training. Every arm is trained with three seeds and evaluated on the same programs. {{tab:e02-566e}} gives the results. The typed interface (C) answered more questions correctly than the text tool (B) on every split and seed. Beyond the training length and on held-out pairs the mean difference was 0.06 to 0.10, above a conservative two-standard-error bound. At the training length it was 0.02, within the bound. B chose actions more accurately than C, so C's advantage arises after the action is chosen. Replacing the integer oracle with the delta-rule memory (D) changed no answer, and the delta-rule executor matched its shadow oracle on every action. All arms got worse on longer programs, and so did the accuracy of their chosen actions. The controller, not the machine, limits accuracy.

{{e:E03}} asks whether feedback that enters the model, rather than text or the heads, improves control. Its programs add statements such as “Copy c to e.”, which take two machine steps: read c, then write the value read to e. The value is not in the text, so the controller must route the read's reply into its next decision. At each step the controller chooses a write, a read, or the end of the statement, with at most three steps per statement, and the step's action and reply form a small feedback code. The arms in {{tab:e03-arms}} differ only in where that code goes ({{fig:roadmap}} places this experiment after {{e:E02}}). All arms drive the delta-rule memory with a shadow oracle.

{{anim:e03}}

{{tab:e03-ff00}} gives the results on the same test splits as {{e:E02}}. L and S beat T, H, and N on every split and seed, by 0.08 to 0.17 at the training length and by 0.31 to 0.53 at 32 and 64 statements (seed means), so the gain survives comparison with the native loop. But S, whose vectors carry no feedback, matched or beat L up to 32 statements. L led only at 64 statements, by 0.05. Most of the improvement therefore comes from trained vectors in the model's input, not from feedback through the model. L and S also use more model computation than H and N and train through the frozen model, so the comparison is not matched for work. Typed feedback to the heads (H) again beat text (T), by 0.04 to 0.07. The delta-rule memory matched its oracle on every action of every arm, and runs interrupted between the read and the write of a copy resumed through JSON identically.

{{e:E09}} asks whether the length loss comes from reading a long context. It reuses the task, frozen model, and heads of {{e:E02}} and changes only what each forward pass reads. Arm S reads the preamble and one statement per pass, so the machine holds all state. C reads the whole program. B is the text tool. W reads one statement and has no machine. S+delta runs S's heads on the delta-rule memory. We added a 256-statement split. The predictions and a compounding baseline were fixed before the run.

{{anim:e09}}

S answered every question correctly at every length, with zero executor mismatches, while C and B fell to 0.13 and 0.11 at 256 statements. Prediction 1 held: S beat C by more than a conservative bound at 64 and 256 statements, by 0.71 and 0.87. Prediction 2 held only vacuously: S made no errors, so the compounding baseline was 1.000 at every length and constrained nothing. Prediction 3 failed: W scored 0.50 on programs of 2 to 8 statements against a ceiling of 0.15. W answers 0 to every question, which is right whenever the record was never written, and short programs have many such questions. We count the prediction as failed and read it as a ceiling set too low, not as leaked state.

The task has 128 distinct statements and S trained on all of them, so the perfect score could be a lookup. A follow-up, with its predictions again fixed first, tested the 8 statements held out of training (record g or h with a value from 12 to 15). S chose the right action for 7 of the 8 in every seed and answered 0.98 of the questions on programs containing them, against 0.83 for C. The prediction of at least 0.90 on the unseen statements was not met (0.875), so we report it as inconclusive, not as support. A random model with no pretraining got 2 of 8, so S is more than a lookup. Together: long context causes the loss, and S reads most unseen statements. The task is still small, and its statements do not depend on each other.

6 Limitations

The results are conformance tests on finite workloads and do not prove exactness for other inputs, sizes, or horizons. All conformance runs use eager PyTorch on CPU. GPUs, fused or chunked kernels, and the output normalization and gating of a complete Gated DeltaNet layer are untested, and Section 3.2 shows that such details can matter. The machines are small: 16 memory words, transducers with at most six states, a stack of depth 8, 32×32 grids, graphs of up to 4,096 vertices, and SAT instances of up to 100 variables. Timings come from shared machines and show orders of magnitude only. Host code validates arguments before the tensor update, so the results cover storage, readout, and transitions, not validation. The sweeps of 105 and 106 actions use one seed. The controller studies use one frozen 135M-parameter model with trained heads, one task family, and three seeds. In {{e:E03}}, the latent arms use more model positions than the head and native arms, observation-only feedback was not tested, and the steering control was added after a pilot. In {{e:E09}}, the unseen-statement result is a count out of 8 per seed, the statements do not depend on each other, one prediction held only vacuously, and another had a ceiling set too low.

7 Conclusion

With gates fixed at 0 or 1 and one-hot addressing, the Gated DeltaNet recurrence implements random-access memory and, with a one-hot pointer, a bounded stack. Two-layer ReLU circuits implement finite-state transducers. In the tested configurations, each implementation matched its integer oracle at every action with zero residue. With these executors, a controller on a frozen language model answered more questions correctly through a typed internal interface than through a text tool on programs longer than those seen in training, and the compiled executor gave the same answers as the native one. On long programs the controller's actions limit accuracy. Reading the program one statement at a time, with the machine holding the state, removed that limit on a task whose statements are independent. Trained input vectors in the frozen model improved the actions substantially, with or without the machine's feedback, so the evidence favors trained steering over latent feedback. The other machines show that exact tensor execution is achievable in float32 and float64 within declared limits, but it is rarely faster than conventional code. Whether it pays off by being differentiable or composable with a model remains to be shown.
